# PKG_WORKSPACE

Пакет `sql/27_workspace.sql` расширяет серверный API настройками поставщиков, финансовыми целями, уведомлениями и тегами. Собственного DDL нет; используются согласованная ER и одобренные поля `user_settings.risk_free_rate_percent` / `risk_free_currency`. Выдаётся только `EXECUTE` прикладной роли; прямой доступ runtime-пользователя к таблицам не нужен. Скрипт выполняется после схемы, миграции настроек и `PKG_AUTH`, в схеме `PROXIMA_OWNER`.

Каждый метод принимает токен и вызывает `PKG_AUTH.REQUIRE_USER`; разрешены только действующие `PrivateInvestor` и `FinancialConsultant`. Портфели, активы, цели, уведомления и теги проверяются на принадлежность пользователю. Архивный портфель или цель недоступны. Несуществующие и чужие ресурсы возвращают одинаковую ошибку `-20601`. Администратор пользуется административным API, а не обходит проверку владельца через этот пакет.

Все изменения и аудит находятся в транзакции вызывающего кода. В процедурах нет `COMMIT`: ошибка откатывает только изменения процедуры к её savepoint. В журнал попадают действие и идентификатор ресурса, без токенов, ключей и содержимого уведомлений. Идемпотентное включение/выключение тега не создаёт повторные связи.

## Контракт API

`p_token VARCHAR2` — первый параметр всех методов. Идентификаторы входа — `RAW(16)`, в курсорах — 32 шестнадцатеричных символа. `p_result OUT SYS_REFCURSOR` — последний параметр методов чтения/прогноза. Даты возвращаются в типах Oracle без текстового форматирования.

| Метод после p_token | Назначение / результат |
|---|---|
| `get_settings(p_result)` | `quote_provider_kind`, `exchange_rate_provider_kind`, `quote_api_key_configured` (0/1), `risk_free_rate_percent`, `risk_free_currency`. Если настройки ещё не созданы, курсор пуст. |
| `save_settings(p_quote_provider_kind VARCHAR2, p_exchange_rate_provider_kind VARCHAR2, p_risk_free_rate_percent NUMBER DEFAULT NULL, p_risk_free_currency VARCHAR2 DEFAULT NULL)` | Полное сохранение настроек владельца. Имена непустые, 1–64 символа после удаления крайних пробелов; имена провайдеров не зашиты в бизнес-API. Пара годовой безрисковой ставки в процентах и валюты либо вся NULL (сбрасывает прежнее значение), либо вся заполнена; ставка больше −100%, валюта существует в справочнике. |
| `list_goals(p_portfolio_id RAW, p_result)` | Неархивные цели своего активного портфеля: `goal_id`, `portfolio_id`, `title`, `target_amount`, `currency`, `monthly_contribution`, `expected_annual_return_percent`, `target_date`, `created_at`. |
| `save_goal(p_portfolio_id RAW, p_id IN OUT RAW, p_title VARCHAR2, p_target_amount NUMBER, p_currency VARCHAR2, p_monthly_contribution NUMBER, p_expected_annual_return NUMBER, p_target_date DATE)` | При NULL `p_id` создаёт цель и возвращает ID, иначе изменяет существующую цель того же портфеля. `p_expected_annual_return` задаётся в годовых процентах: 12 означает 12%, не 0.12%. |
| `archive_goal(p_id RAW)` | Исключить свою цель из активных списков и прогнозирования. |
| `project_goal(p_id RAW, p_initial_capital NUMBER, p_months NUMBER, p_result)` | Сценарный прогноз в валюте цели; курсор из одной строки, колонки описаны ниже. |
| `list_notifications(p_offset NUMBER, p_limit NUMBER, p_result)` | Только свои неудалённые уведомления: `notification_id`, `title`, `message CLOB`, `source`, `severity`, `created_at_utc`. Сначала новые, при одинаковом времени — ID по убыванию. Offset: целое 0–1 000 000; limit: целое 1–200. |
| `dismiss_notification(p_id RAW)` | Поставить время удаления своему активному уведомлению. |
| `list_tags(p_result)` | `tag_id`, `name` только своего пользователя, сортировка по имени и ID. |
| `save_tag(p_name VARCHAR2, p_id IN OUT RAW)` | При NULL ID создать, иначе переименовать свой тег. Имя 1–255 символов; уникальность соответствует существующему ограничению `(owner_user_id,name)` и чувствительна к регистру. |
| `set_asset_tag(p_asset_id RAW, p_tag_id RAW, p_enabled NUMBER)` | Включить (1) / выключить (0) связь своего неархивного актива со своим тегом. |
| `delete_tag(p_id RAW)` | Удалить свой тег и его связи с активами в одной транзакции. |

`quote_api_key` не возвращается ни одним методом и не записывается этим API. Уже существующее значение сохраняется при изменении настроек. Ключи адаптеров передаются через внешнюю конфигурацию/секреты; не вводится хранение новых ключей открытым текстом и не имитируется шифрование без управления ключами. Флаг `quote_api_key_configured` описывает только наличие значения старого поля БД, а не работоспособность внешнего API или наличие внешнего секрета.

## Формула цели

Пользователь задаёт начальный капитал `C`, пополнение в конце каждого месяца `P`, ожидаемую годовую доходность в процентах `r` и горизонт `n` месяцев. Доходность должна быть больше −100%, капитал и пополнение неотрицательны, цель положительна. Для сохранённых денежных параметров применяется существующая точность столбцов, ставка хранится с шестью знаками после запятой. Допустимый горизонт — целое от 0 до 1200 месяцев.

`i = (1 + r / 100)^(1/12) − 1`

`FV = C × (1+i)^n + P × ((1+i)^n − 1) / i`

При нулевой ставке: `FV = C + P × n`. При нулевом горизонте: `FV = C`. Отрицательная ожидаемая доходность допустима в указанном диапазоне. Результат не является ML-прогнозом, не учитывает инфляцию, налоги, комиссии будущих сделок или изменение валютного курса; все суммы уже выражены в валюте цели. `target_date` — сохранённая дата пожелания пользователя, не скрытый источник горизонта: горизонт всегда передан явно. Числовое переполнение возвращает ошибку параметров, а не вымышленный результат.

Курсор `project_goal`: `months`, `initial_capital`, `monthly_contribution`, `expected_annual_return_percent`, `effective_monthly_rate` (доля за месяц), `projected_amount`, `target_amount`, `currency`, `target_reached` (0/1). Никакого сохранения вычисленных значений в `goals` нет.

## Ошибки

- `-20301`: отсутствует действующая сессия (контракт `PKG_AUTH`).
- `-20600`: роль не инвестор/консультант.
- `-20601`: ресурс недоступен.
- `-20602`: некорректные параметры/неподдерживаемый числовой диапазон.
- `-20603`: имя тега уже используется этим владельцем.

## Проверки

`sql/101_workspace_tests.sql` — подготовленные SQL-интеграционные проверки через доверенную SYS-сессию внутри прикладной PDB. Фикстуры изолированы случайными ID и откатываются; хеши сессий создаются только в доверенной фикстуре для проверки API без затрат на многократный PBKDF2. Это не публичный способ выпуска токенов. Скрипт не запускается автоматически и не является доказательством прохождения до реального выполнения на Oracle. Он проверяет формулу при нулевой, положительной и отрицательной ставке, крайние горизонты, права и фильтрацию, отсутствие выдачи ключа, идемпотентность тегов, откат к savepoint и аудит.
