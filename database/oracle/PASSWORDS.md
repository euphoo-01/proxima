# Пароли Oracle

`PKG_PASSWORD` — внутренний пакет владельца; EXECUTE не выдаётся PROXIMA_APP/PUBLIC. Владельцу нужна прямая привилегия `GRANT EXECUTE ON SYS.DBMS_CRYPTO TO PROXIMA_OWNER`. Установка из SYS: `ALTER SESSION SET CURRENT_SCHEMA=PROXIMA_OWNER`, затем `@21_password.sql`; проверить ALL_ERRORS перед `@98_password_tests.sql`.

`hash_password(VARCHAR2) RETURN VARCHAR2` принимает 12–128 символов, кодирует AL32UTF8 и создаёт случайную 16-байтовую соль через DBMS_CRYPTO.RANDOMBYTES. Формат: `PBKDF2-SHA256$600000$<32 hex соли>$<64 hex ключа>`, всего 118 символов. Значение помещается в существующее users.password_hash. Пароль/соль/ключ не выводятся в журнал тестов.

PBKDF2 вычисляет один 32-байтовый блок по стандартной цепочке HMAC-SHA256 и XOR; примитив HMAC предоставляет [Oracle DBMS_CRYPTO.MAC](https://docs.oracle.com/en/database/oracle/oracle-database/26/arpls/DBMS_CRYPTO.html). Это совместимый путь для установленной Oracle 26.3, где DBMS_CRYPTO.PBKDF2 отсутствует. `derive_key(password,salt,iterations)` доступен внутренним тестам с 1–600000 итерациями; рабочий формат всегда требует ровно 600000. Его нельзя выдавать внешнему клиенту как самостоятельный низкоуровневый API.

`verify_password(password,encoded) RETURN BOOLEAN` отклоняет неправильный формат/длину и иной work factor. Для корректного формата вычисляет все 600000 HMAC и сравнивает все 32 байта без раннего выхода. Это фиксированный объём сравнения на уровне исходного PL/SQL, не формальное обещание постоянного времени исполнения виртуальной машины. Ошибки БД не маскируются под неверный пароль. Защита от перебора, ограничение частоты входов и одинаковые ответы для отсутствующего пользователя должны обеспечиваться вызывающим пакетом аутентификации.

`98_password_tests.sql` проверяет известные SHA256-векторы для password/salt с 1/2/4096 итерациями, отдельный Unicode-вектор с кириллицей и emoji (эталон Python hashlib.pbkdf2_hmac), независимые соли, правильный/неправильный пароль, повреждённый формат, уменьшенный work factor и границы валидации. Векторы получены независимо от Oracle реализации. Тест выводит длительность одной рабочей операции в секундах; итоговую производительность следует оценивать на целевой машине. Тест не создаёт учётных записей, не меняет таблицы и не выполняет COMMIT.
